FROM INSTALL TO VALIDATION

A familiar fit.
A tiny API.

Import the plugin once, then add .phone() to your string schema. Yup stays your application’s peer dependency.

01 / INSTALL

Add it to your project.

npm install yup yup-phone

Already using Yup 0.32? Keep it:

npm install yup@0.32.11 yup-phone@2View on npm ↗
02 / USE IT 
import * as yup from 'yup';
import 'yup-phone';

const phone = yup.string().phone('US', true);

phone.isValidSync('(415) 555-2671');
// → true. That’s it.
const yup = require('yup');
require('yup-phone');

const phone = yup.string().phone('US', true);

phone.isValidSync('(415) 555-2671');
// → true. Same API, different import.
import * as yup from 'yup';
import 'yup-phone';

const schema = yup.object({
  phone: yup.string().required().phone('US', true),
});

type Contact = yup.InferType<typeof schema>;
// { phone: string } — types stay intact.

✓ Side-effect import. Familiar Yup chaining. Built-in declarations.

THE ENTIRE PHONE API

Three arguments.
You’re in control.

Choose a parsing region, decide how strictly to match it, and customize your error message.

schema.phone(countryCode?, strict?, errorMessage?)Returns the same schema
01

countryCode

string · default 'IN'

The parsing region for national numbers. International numbers keep their own calling code.

.phone('GB')
02

strict

boolean · default false

When enabled, checks the selected region’s rules and calling code. Loose mode accepts valid international numbers.

.phone('US', true)
03

errorMessage

string · optional

Your own Yup error message, with support for path interpolation.

.phone('US', true, 'Invalid phone')

Ask a question ↗
Does v2 work with my existing Yup version?

Yes, the declared peer range is ^0.32.11 || ^1.0.0. The original phone tests remain unchanged. Version 2 requires Node 18+ and modern browsers with ES2020 support.

What is the difference between strict and loose?

Loose mode uses the region to parse national numbers, while allowing valid international numbers from other regions. Strict mode additionally checks the selected region’s rules and calling code. Try the International example, then toggle Strict region in the playground.

How do I make a phone field optional?

The default phone check still rejects empty strings, undefined, and null. To allow blank values, apply it only when a value is present: 

const optionalPhone = yup.lazy((value) =>
  value == null || value === ''
    ? yup.string().nullable()
    : yup.string().phone('US')
);

The playground’s Allow empty values option demonstrates this explicit workaround.

Why is .phone missing from my schema?

Import 'yup-phone' before constructing the schema, and keep one supported Yup instance in your application. The package registers its method on your application’s peer dependency. TypeScript users should use Yup’s built-in declarations and remove obsolete @types/yup.

How do I keep my required-field error message?

Put required before phone:

yup.string()
  .required('Phone is required')
  .phone('US');

This order makes the required message win for an empty string.

Where can I find release and security information?

See the releases and benchmark artifacts and the release setup guide. GitHub Actions checks compatibility, package formats, dependency audits, and CodeQL. Versioned npm releases include provenance.
